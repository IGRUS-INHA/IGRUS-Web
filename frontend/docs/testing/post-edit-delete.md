# 게시글 수정/삭제 기능 브라우저 테스트 가이드

## 개요

이 문서는 게시글 수정/삭제 기능의 브라우저 테스트 시나리오를 정의합니다.

**테스트 대상 기능:**

- 작성자 본인: 게시글 수정/삭제 버튼 표시
- 비작성자: 신고 버튼만 표시 (작성자 차단 기능 제거됨)
- 게시글 수정 페이지 (`/board/:boardType/:postId/edit`)
- 게시글 삭제 API 연동

**구현 파일:**

- `frontend/src/pages/board/PostDetailPage.tsx`
- `frontend/src/pages/board/PostEditPage.tsx`
- `frontend/src/constants/board.ts`

---

## 사전 준비

### 필요 계정

- **계정 A (작성자)**: 테스트 게시글을 작성할 계정
- **계정 B (비작성자)**: 다른 사용자 계정

### 테스트 데이터

1. 계정 A로 로그인하여 테스트용 게시글 작성
   - 게시판: 자유게시판 (`/board/general`)
   - 제목: "테스트 게시글 - 수정/삭제 기능 검증"
   - 내용: "이 게시글은 수정/삭제 기능 테스트용입니다."
2. 게시글 ID 기록 (URL에서 확인)

---

## 테스트 시나리오

### 시나리오 1: 작성자 메뉴 확인

**목적:** 작성자에게 수정/삭제 버튼이 표시되는지 확인

**단계:**

1. 계정 A로 로그인
2. 자신이 작성한 게시글 상세 페이지 이동
   - URL: `/board/general/{postId}`
3. 우측 상단 MoreHorizontal(⋯) 메뉴 클릭

**예상 결과:**

- "수정하기" 버튼 표시 (Edit 아이콘 포함)
- "삭제하기" 버튼 표시 (Trash2 아이콘, 빨간색)
- "신고하기" 버튼 **없음**

**검증 항목:**

- [ ] MoreHorizontal 메뉴가 정상적으로 열림
- [ ] "수정하기" 버튼이 표시됨
- [ ] "삭제하기" 버튼이 표시됨 (빨간색)
- [ ] "신고하기" 버튼이 표시되지 않음

---

### 시나리오 2: 비작성자 메뉴 확인

**목적:** 비작성자에게 신고 버튼만 표시되는지 확인

**단계:**

1. 계정 B로 로그인 (또는 로그아웃 후 다른 계정으로 로그인)
2. 계정 A가 작성한 게시글 상세 페이지 이동
   - URL: `/board/general/{postId}`
3. 우측 상단 MoreHorizontal(⋯) 메뉴 클릭

**예상 결과:**

- "신고하기" 버튼만 표시
- "수정하기", "삭제하기" 버튼 **없음**
- "작성자 차단" 버튼 **없음** (제거됨)

**검증 항목:**

- [ ] MoreHorizontal 메뉴가 정상적으로 열림
- [ ] "신고하기" 버튼만 표시됨
- [ ] "수정하기", "삭제하기" 버튼이 표시되지 않음
- [ ] "작성자 차단" 버튼이 표시되지 않음

---

### 시나리오 3: 게시글 수정 플로우

**목적:** 게시글 수정 기능이 정상적으로 작동하는지 확인

**단계:**

1. 계정 A로 로그인
2. 자신이 작성한 게시글 상세 페이지 이동
3. MoreHorizontal(⋯) 메뉴에서 "수정하기" 클릭
4. 수정 페이지 로드 확인
   - URL: `/board/general/{postId}/edit`
5. 폼에 기존 내용이 채워져 있는지 확인
6. 제목 수정: "테스트 게시글 - 수정됨"
7. 내용 수정: "이 게시글은 수정되었습니다."
8. "수정하기" 버튼 클릭

**예상 결과:**

- 수정 페이지에 기존 제목, 내용이 폼에 표시됨
- 익명, 질문 설정이 유지됨
- 수정 완료 후 게시글 상세 페이지로 리다이렉트
- 변경된 제목, 내용이 즉시 반영됨

**검증 항목:**

- [ ] 수정 페이지로 정상 이동
- [ ] 기존 제목이 입력 필드에 표시됨
- [ ] 기존 내용이 MDEditor에 표시됨
- [ ] 익명, 질문 등 설정이 유지됨
- [ ] 제목, 내용 수정 가능
- [ ] "수정하기" 버튼 클릭 시 로딩 상태 표시
- [ ] 수정 성공 시 상세 페이지로 리다이렉트
- [ ] 변경 사항이 즉시 반영됨
- [ ] 게시판 목록에서도 제목이 업데이트됨

---

### 시나리오 4: 게시글 삭제 플로우

**목적:** 게시글 삭제 기능이 정상적으로 작동하는지 확인

**단계:**

1. 계정 A로 로그인
2. 자신이 작성한 게시글 상세 페이지 이동
3. MoreHorizontal(⋯) 메뉴에서 "삭제하기" 클릭
4. 확인 다이얼로그 확인
5. "취소" 버튼 클릭
6. 게시글이 유지되는지 확인
7. 다시 "삭제하기" 클릭
8. 확인 다이얼로그에서 "확인" 클릭

**예상 결과:**

- "이 게시글을 삭제하시겠습니까?\n삭제된 게시글은 복구할 수 없습니다." 메시지 표시
- 취소 시: 게시글이 삭제되지 않고 유지됨
- 확인 시: 게시글이 삭제되고 게시판 목록으로 리다이렉트
- 목록에서 삭제된 게시글이 보이지 않음

**검증 항목:**

- [ ] 삭제 확인 다이얼로그 표시됨
- [ ] 확인 메시지가 명확함
- [ ] "취소" 클릭 시 게시글 유지
- [ ] "확인" 클릭 시 게시판 목록으로 리다이렉트
- [ ] 삭제된 게시글이 목록에서 제거됨
- [ ] 삭제된 게시글 URL에 직접 접근 시 404 또는 적절한 에러 메시지

---

### 시나리오 5: 권한 없는 수정 시도

**목적:** 비작성자가 수정 페이지에 접근했을 때 권한 체크가 정상 작동하는지 확인

**단계:**

1. 계정 B로 로그인 (비작성자)
2. 브라우저 주소창에 수정 URL 직접 입력
   - URL: `/board/general/{postId}/edit`

**예상 결과:**

- 폼이 표시되지 않음
- "수정 권한이 없습니다." 메시지 표시
- "뒤로 가기" 버튼 표시

**검증 항목:**

- [ ] 수정 폼이 렌더링되지 않음
- [ ] "수정 권한이 없습니다." 메시지 표시
- [ ] "뒤로 가기" 버튼이 작동함
- [ ] 뒤로 가기 클릭 시 게시글 상세 페이지로 이동

---

### 시나리오 6: 에러 처리 확인

**목적:** 에러 상황에서 적절한 메시지가 표시되는지 확인

#### 6-1: 존재하지 않는 게시글 수정 시도

**단계:**

1. 계정 A로 로그인
2. 존재하지 않는 게시글 ID로 수정 페이지 접근
   - URL: `/board/general/999999/edit`

**예상 결과:**

- "게시글을 불러올 수 없습니다." 메시지 표시
- "뒤로 가기" 버튼 표시

**검증 항목:**

- [ ] 로딩 상태 표시 후 에러 메시지
- [ ] "게시글을 불러올 수 없습니다." 메시지
- [ ] "뒤로 가기" 버튼 작동

#### 6-2: 네트워크 에러 시뮬레이션

**단계:**

1. 브라우저 개발자 도구 → Network 탭
2. "Offline" 모드 활성화
3. 게시글 수정 시도

**예상 결과:**

- 적절한 에러 메시지 표시

**검증 항목:**

- [ ] 네트워크 에러 시 사용자에게 알림
- [ ] 에러 메시지가 명확함

---

### 시나리오 7: 캐시 무효화 확인

**목적:** 수정/삭제 후 데이터 동기화가 정상적으로 이루어지는지 확인

#### 7-1: 수정 후 목록 동기화

**단계:**

1. 게시글 수정 완료
2. 게시판 목록 페이지로 이동
3. 수정된 제목이 목록에 반영되었는지 확인

**예상 결과:**

- 목록에서 수정된 제목이 즉시 표시됨

**검증 항목:**

- [ ] 수정 후 목록에서 제목이 업데이트됨
- [ ] 새로고침 없이 변경사항 반영

#### 7-2: 삭제 후 목록 동기화

**단계:**

1. 게시글 삭제 완료
2. 게시판 목록 확인

**예상 결과:**

- 삭제된 게시글이 목록에서 제거됨

**검증 항목:**

- [ ] 삭제된 게시글이 목록에 없음
- [ ] 새로고침 없이 변경사항 반영

## 추가 테스트 케이스

### Edge Case 1: 로딩 중 페이지 이탈

**단계:**

1. 게시글 수정 중
2. 브라우저 뒤로 가기 또는 다른 페이지로 이동

**예상 결과:**

- 변경사항이 저장되지 않음 (정상 동작)

**검증 항목:**

- [ ] 변경사항 미저장
- [ ] 원본 게시글 유지

### Edge Case 2: 폼 검증 오류

**단계:**

1. 수정 페이지에서 제목을 비움
2. "수정하기" 버튼 클릭

**예상 결과:**

- "제목을 입력해주세요" 에러 메시지 표시
- API 호출 안 됨

**검증 항목:**

- [ ] 제목 필드에 에러 메시지 표시
- [ ] API 호출이 발생하지 않음
- [ ] 사용자가 수정 페이지에 유지됨

### Edge Case 3: 동시 수정 시도

**단계:**

1. 두 개의 브라우저 탭에서 같은 게시글 수정 페이지 열기
2. 탭 A에서 수정 완료
3. 탭 B에서 수정 시도

**예상 결과:**

- 탭 B의 수정도 정상적으로 처리됨 (마지막 수정이 반영됨)

**검증 항목:**

- [ ] 두 번째 수정이 정상적으로 처리됨
- [ ] 에러가 발생하지 않음
