# Events 테스트 가이드

행사 신청 취소 요청, 운영진 취소 요청 알림(`/notify`), 신청 인원 비공개, 신청자 CSV 내보내기에 대한 수동 브라우저 테스트 시나리오입니다.

> 관련 문서: [event-edit-delete.md](event-edit-delete.md), [event-filter-test-guide.md](event-filter-test-guide.md)

## 1. 수동 브라우저 테스트

#### 1.1 신청 취소 요청 (사유 입력)

**시나리오**: 신청한 회원이 사유를 적어 취소를 요청한다. 즉시 취소되지 않고 운영진 확인을 기다린다.

1. 정회원으로 로그인 후 `/events` 에서 신청한 행사를 펼친다
2. "신청 취소 요청" 버튼 클릭 → "신청 취소 요청 사유" 다이얼로그가 열린다
3. 사유가 비어 있거나 공백뿐이면 "확인" 버튼이 비활성인지 확인, 500자를 넘겨 입력되지 않는지 확인
4. 사유 입력 후 "확인"
5. **예상 결과**:
   - "취소 요청이 접수되었습니다. 운영진 확인 후 취소됩니다." 안내
   - 버튼이 비활성 "취소 요청됨 (운영진 확인 대기)" 로 바뀐다 (새로고침 후에도 유지)
   - 신청 자체는 유지된다 (마이페이지 신청 내역에 그대로 있음)
6. **Network 탭 확인**:
   - URL: `POST .../api/v1/events/{eventId}/registrations/cancel-request`, body `{ "reason": "..." }`
   - Status: 200 OK
   - 이후 `GET .../api/v1/events/{eventId}` 응답의 `cancelRequested: true`
7. **Console 탭 확인**:
   - 에러 없음

#### 1.2 신청 취소 요청 에러

**시나리오**: 중복 요청 등 실패 케이스의 안내 문구 확인

1. 이미 취소 요청한 신청에 다시 요청 (다른 탭에서 먼저 요청해 둔 뒤, 새로고침하지 않은 탭에서 요청)
2. **예상 결과**:
   - 409 `EVENT_CANCEL_ALREADY_REQUESTED` → "이미 취소 요청한 신청입니다."
   - 400 `EVENT_ALREADY_CANCELED` → "이미 취소된 신청입니다."
   - 400 `EVENT_NOT_CANCELABLE` → "취소된 행사의 신청은 취소할 수 없습니다."
3. **Network 탭 확인**:
   - URL: `POST .../api/v1/events/{eventId}/registrations/cancel-request`
   - Status: 409 / 400

#### 1.3 운영진 취소 요청 알림 (`/notify`)

**시나리오**: 운영진이 취소 요청 목록에서 사유를 확인하고 실제 취소를 처리한다.

1. OPERATOR 이상으로 로그인 → 사이드바 "취소 요청 알림" 클릭 (`/notify`)
2. 각 항목에 행사명, 신청자 이름/학번(외부인 배지), 요청 시각, 취소 사유가 최신 요청순으로 보이는지 확인
3. 대기 중인 항목의 "취소하기" 클릭 → 확인창에서 "확인"
4. **예상 결과**:
   - "신청을 취소했습니다." 토스트
   - 해당 항목은 목록에 남고 버튼 대신 "취소됨" 배지가 표시된다
   - 행사명 링크로 이동한 신청자 관리 페이지에서 해당 신청 상태가 "취소"
   - 확인창에서 "취소"를 누르면 요청이 나가지 않는다
   - 요청이 없으면 "취소 요청이 없습니다.", 20건 초과 시 페이지네이션 표시
5. **Network 탭 확인**:
   - URL: `GET .../api/v1/registrations/cancel-requests?page=0&size=20` → 200 OK
   - URL: `POST .../api/v1/registrations/{registrationId}/cancel` → 200 OK, 이후 목록 재조회
6. **권한 확인**:
   - 정회원 이하로 `/notify` 직접 접근 → "접근 권한 부족" 토스트 후 홈으로 이동, 사이드바에 메뉴 없음
7. **Console 탭 확인**:
   - 에러 없음

#### 1.3.1 취소 요청 거절

**시나리오**: 운영진이 취소 요청을 거절하면 요청이 없던 것으로 되돌아가고 신청은 유지된다.

1. OPERATOR 이상으로 `/notify` 접속 → 대기 중인 항목의 "거절" 클릭 → 확인창에서 "확인"
2. **예상 결과**:
   - "취소 요청을 거절했습니다. 신청은 유지됩니다." 토스트
   - 해당 항목이 목록에서 사라진다 ("취소됨" 배지로 남지 않음)
   - 신청자 관리 페이지에서 해당 신청의 상태는 그대로이고 "취소 요청" 배지가 없다
   - 요청했던 회원으로 로그인하면 행사에 다시 "신청 취소 요청" 버튼이 보이고 재요청이 가능하다
   - 취소/거절 요청이 진행 중인 동안 모든 "취소하기"/"거절" 버튼이 비활성
3. 다른 탭에서 이미 취소 또는 거절한 항목에 "취소하기"/"거절" 클릭
4. **예상 결과**:
   - 거절: 400 `EVENT_CANCEL_REQUEST_NOT_PENDING` → "이미 처리된 요청입니다." 토스트 후 목록 새로고침
   - 취소하기: 400 `EVENT_INVALID_REGISTRATION_STATUS` → 같은 토스트 후 목록 새로고침 (실패해도 목록은 항상 재조회된다)
5. **Network 탭 확인**:
   - URL: `POST .../api/v1/registrations/{registrationId}/cancel-request/reject` → 200 OK, 이후 `GET .../api/v1/registrations/cancel-requests` 재조회
6. **운영진 본인 신청**: 운영진이 자기 신청을 취소 요청하면 `GET .../api/v1/admin/events/{eventId}` 응답의 `cancelRequested: true` 로 "취소 요청됨 (운영진 확인 대기)" 가 표시된다
7. **탈퇴 회원**: 탈퇴한 회원의 요청은 이름이 "탈퇴한 사용자", 학번 없이 표시된다
8. **Console 탭 확인**:
   - 에러 없음

#### 1.4 신청 인원 현황은 운영진만

**시나리오**: 현재 신청 인원은 운영진에게만 보이고, 정원은 모두에게 보인다.

1. 정회원(또는 비로그인, 외부 신청 허용 행사)으로 `/events` 에서 정원이 있는 행사를 펼친다
2. **예상 결과 (비운영진)**:
   - "모집 정원 · 최대 N명" 만 표시, "N / 정원" 숫자와 진행바 없음
   - 우측 통계에 "총 참여자" 항목 없음
   - "0명", "0 / N" 같은 잘못된 값이 어디에도 보이지 않음
   - 신청하기/신청 불가 버튼과 모집 상태 배지는 정상 동작 (정원 마감 행사는 "신청 불가")
3. 운영진으로 같은 행사를 펼친다
4. **예상 결과 (운영진)**:
   - "모집 현황 N / 정원" 과 진행바, 통계 "총 참여자" 표시
5. **Network 탭 확인**:
   - 비운영진: `GET .../api/v1/events`, `GET .../api/v1/events/{eventId}` 응답의 `currentCount: null`
   - 운영진: `GET .../api/v1/admin/events...` 응답에 `currentCount` 숫자

#### 1.5 신청자 CSV 내보내기

**시나리오**: 운영진이 신청자 전체를 CSV로 내려받는다.

1. 운영진으로 `/events/{eventId}/registrations` 접속
2. 신청자가 100명을 넘는 행사라면 목록·대시보드 합계가 전체 인원과 일치하는지 확인
3. 취소 요청이 있는 신청의 상태 옆에 "취소 요청" 배지(마우스를 올리면 사유)가 보이는지 확인
4. "CSV로 내보내기" 클릭
5. **예상 결과**:
   - `{행사명}_신청자_{YYYY-MM-DD}.csv` 다운로드 (신청자가 없으면 버튼 비활성)
   - 엑셀에서 열었을 때 한글이 깨지지 않음
   - 컬럼: 이름, 학번, 학과, 학년, 이메일, 전화번호, 구분, 상태, 신청일시, 취소 요청 사유, 취소 요청 일시
   - 행 수 = 전체 신청자 수 (취소 포함), 상태는 화면 배지와 같은 한글 라벨
   - 쉼표/따옴표/줄바꿈이 들어간 취소 사유가 한 셀에 온전히 들어감
   - 이름이나 사유가 `=`, `+`, `-`, `@` 로 시작하는 신청(예: 외부인 이름 `=1+1`)은 앞에 `'` 가 붙어 수식으로 실행되지 않음
6. **Network 탭 확인**:
   - URL: `GET .../api/v1/events/{eventId}/registrations?page=0&size=100&sort=registeredAt,ASC` (100명 초과 시 `page=1`… 이어서 호출)
   - 내보내기 클릭 시 추가 요청 없음 (화면에 로드된 전체 목록으로 생성)
7. **Console 탭 확인**:
   - 에러 없음
