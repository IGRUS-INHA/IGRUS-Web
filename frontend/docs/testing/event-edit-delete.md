# 행사 수정/삭제 기능 테스트 시나리오

이 문서는 행사 수정 및 삭제 기능에 대한 테스트 시나리오를 정의합니다.

## 테스트 대상 기능

- EventDetailPage: More Menu 및 삭제 기능
- EventEditPage: 행사 수정 폼
- useEvents.ts: useUpdateEvent, useDeleteEvent 훅

---

## 1. More Menu 표시 테스트

### 1.1 권한 있는 사용자에게 More Menu 표시

**목적**: 작성자 또는 권한이 있는 사용자에게만 More Menu가 표시되는지 확인

**전제 조건**:

- OPERATOR 이상 권한으로 로그인
- 자신이 작성한 행사 존재

**테스트 단계**:

1. 자신이 작성한 행사의 상세 페이지로 이동 (`/events/{eventId}`)
2. 우측 상단 헤더 영역 확인

**예상 결과**:

- ✅ 우측 상단에 점 3개 (⋯) 아이콘 표시
- ✅ 아이콘 클릭 시 드롭다운 메뉴 열림
- ✅ "수정하기", "삭제하기" 메뉴 항목 표시

**검증 항목**:

- UI에 More Menu 버튼 존재
- 메뉴 항목이 올바르게 렌더링됨

---

### 1.2 권한 없는 사용자에게 More Menu 숨김

**목적**: 작성자가 아니거나 권한이 없는 사용자에게는 More Menu가 표시되지 않는지 확인

**전제 조건**:

- 일반 회원으로 로그인
- 다른 사용자가 작성한 행사 존재

**테스트 단계**:

1. 다른 사람이 작성한 행사의 상세 페이지로 이동 (`/events/{eventId}`)
2. 우측 상단 헤더 영역 확인

**예상 결과**:

- ✅ 점 3개 (⋯) 아이콘이 표시되지 않음
- ✅ 수정/삭제 관련 UI 요소가 없음

**검증 항목**:

- `event.canEdit === false` 또는 `event.isAuthor === false`일 때 UI 숨김

---

### 1.3 외부 클릭 시 More Menu 닫힘

**목적**: More Menu가 열린 상태에서 외부를 클릭하면 자동으로 닫히는지 확인

**테스트 단계**:

1. More Menu 아이콘 클릭하여 메뉴 열기
2. 메뉴 외부 영역 클릭

**예상 결과**:

- ✅ More Menu가 자동으로 닫힘

**검증 항목**:

- `useEffect` + `useRef`로 외부 클릭 감지 정상 작동

---

## 2. 행사 삭제 테스트

### 2.1 삭제 기능 성공

**목적**: 권한이 있는 사용자가 행사를 성공적으로 삭제할 수 있는지 확인

**전제 조건**:

- OPERATOR 이상 권한으로 로그인
- 자신이 작성한 행사 존재

**테스트 단계**:

1. 행사 상세 페이지 접근 (`/events/{eventId}`)
2. More Menu (점 3개) 클릭
3. "삭제하기" 메뉴 항목 클릭
4. 확인 다이얼로그에서 "확인" 버튼 클릭

**예상 결과**:

- ✅ 확인 다이얼로그 표시: "이 행사를 삭제하시겠습니까?\n삭제된 행사는 복구할 수 없습니다."
- ✅ `/events` 목록 페이지로 자동 리다이렉트
- ✅ 행사 목록에서 해당 행사 사라짐
- ✅ Network 탭: `DELETE /api/v1/events/{eventId}` (204 No Content)

**검증 항목**:

- API 호출 성공
- 쿼리 무효화 (목록 새로고침)
- 리다이렉트 정상 작동

---

### 2.2 삭제 취소

**목적**: 사용자가 삭제를 취소할 수 있는지 확인

**테스트 단계**:

1. 행사 상세 페이지 접근
2. More Menu → "삭제하기" 클릭
3. 확인 다이얼로그에서 "취소" 버튼 클릭

**예상 결과**:

- ✅ 다이얼로그 닫힘
- ✅ 행사 상세 페이지 유지 (리다이렉트 없음)
- ✅ Network 탭: API 호출 없음

**검증 항목**:

- `window.confirm()` 취소 시 동작 중단

---

### 2.3 삭제 권한 없음 (403)

**목적**: 권한이 없는 사용자가 삭제를 시도할 때 에러 처리가 올바른지 확인

**전제 조건**:

- 일반 회원으로 로그인
- API를 직접 호출하거나 권한이 없는 행사에 강제로 삭제 시도

**테스트 단계**:

1. 권한 없는 행사에 대해 삭제 API 호출

**예상 결과**:

- ✅ alert: "삭제 권한이 없습니다."
- ✅ Network 탭: 403 Forbidden
- ✅ 행사는 삭제되지 않음

**검증 항목**:

- 에러 핸들링 정상 작동
- 403 에러 메시지 표시

---

### 2.4 존재하지 않는 행사 삭제 (404)

**목적**: 존재하지 않는 행사를 삭제하려 할 때 에러 처리가 올바른지 확인

**테스트 단계**:

1. 존재하지 않는 eventId로 삭제 API 호출

**예상 결과**:

- ✅ alert: "행사를 찾을 수 없습니다."
- ✅ Network 탭: 404 Not Found

**검증 항목**:

- 404 에러 메시지 표시

## 3. 행사 수정 페이지 접근 테스트

### 3.1 수정 페이지 접근 성공

**목적**: 권한이 있는 사용자가 수정 페이지에 접근할 수 있는지 확인

**전제 조건**:

- OPERATOR 이상 권한으로 로그인
- 자신이 작성한 행사 존재

**테스트 단계**:

1. 행사 상세 페이지 접근 (`/events/{eventId}`)
2. More Menu → "수정하기" 클릭

**예상 결과**:

- ✅ `/events/{eventId}/edit`로 이동
- ✅ 폼에 기존 데이터 채워져 있음
  - 제목
  - 설명
  - 날짜, 시간
  - 장소
  - 정원
  - 신청 마감일시
- ✅ Network 탭: `GET /api/v1/events/{eventId}` (200 OK)

**검증 항목**:

- 페이지 이동 성공
- 기존 데이터 로딩 및 폼 초기화

---

### 3.2 권한 없는 사용자 리다이렉트

**목적**: 권한이 없는 사용자가 수정 페이지에 접근 시 자동으로 리다이렉트되는지 확인

**전제 조건**:

- 일반 회원으로 로그인
- 다른 사용자가 작성한 행사 존재

**테스트 단계**:

1. URL 직접 입력으로 수정 페이지 접근 (`/events/{eventId}/edit`)

**예상 결과**:

- ✅ 자동으로 `/events/{eventId}` 상세 페이지로 리다이렉트
- ✅ 수정 폼이 렌더링되지 않음

**검증 항목**:

- `useEffect`에서 권한 체크 후 리다이렉트
- `event.canEdit === false && event.isAuthor === false` → 리다이렉트

## 5. 날짜/시간 변환 테스트

### 5.1 ISO 8601 → date/time 변환 정확성

**목적**: API에서 받은 ISO 8601 형식이 폼의 date/time 입력 필드에 올바르게 표시되는지 확인

**테스트 단계**:

1. 수정 페이지 접근
2. 날짜 및 시간 필드 값 확인

**예상 결과**:

- ✅ 날짜: YYYY-MM-DD 형식으로 표시
- ✅ 시간: HH:mm 형식으로 표시
- ✅ 기존 값과 일치

**검증 항목**:

- `toISOString().split('T')[0]` 변환 정확성
- `toTimeString().slice(0, 5)` 변환 정확성

---

### 5.2 date/time → ISO 8601 변환 정확성

**목적**: 폼에서 입력한 date/time이 ISO 8601 형식으로 올바르게 변환되어 API에 전송되는지 확인

**테스트 단계**:

1. 수정 페이지에서 날짜/시간 변경
2. "Update Event" 버튼 클릭
3. Network 탭에서 Request Body 확인

**예상 결과**:

- ✅ `eventStartAt`: ISO 8601 형식 (예: "2024-12-31T14:00:00.000Z")
- ✅ `registrationEndAt`: ISO 8601 형식
- ✅ 타임존 정보 포함

**검증 항목**:

- `new Date(...).toISOString()` 변환 정확성
- 타임존 이슈 없음

## 6. 쿼리 무효화 테스트

### 6.1 삭제 후 목록 새로고침

**목적**: 행사 삭제 후 목록이 자동으로 새로고침되는지 확인

**테스트 단계**:

1. 행사 목록 페이지에서 행사 개수 확인
2. 행사 삭제
3. 목록 페이지로 리다이렉트 후 개수 재확인

**예상 결과**:

- ✅ 삭제된 행사가 목록에서 사라짐
- ✅ Network 탭: `GET /api/v1/events` 재호출

**검증 항목**:

- `queryClient.invalidateQueries({ queryKey: eventKeys.lists() })` 정상 작동

---

### 6.2 수정 후 상세 및 목록 새로고침

**목적**: 행사 수정 후 상세 페이지와 목록이 자동으로 새로고침되는지 확인

**테스트 단계**:

1. 행사 수정
2. 상세 페이지로 리다이렉트 후 변경 내용 확인
3. 목록 페이지로 이동하여 변경 내용 확인

**예상 결과**:

- ✅ 상세 페이지에서 변경 내용 즉시 반영
- ✅ 목록 페이지에서도 변경 내용 반영 (제목, 날짜 등)
- ✅ Network 탭: `GET /api/v1/events/{eventId}` 및 `GET /api/v1/events` 재호출

**검증 항목**:

- `queryClient.invalidateQueries({ queryKey: eventKeys.detail(eventId) })` 정상 작동
- `queryClient.invalidateQueries({ queryKey: eventKeys.lists() })` 정상 작동

## 8. 통합 시나리오 테스트

### 8.1 전체 플로우: 생성 → 수정 → 삭제

**목적**: 행사의 생명 주기 전체 플로우가 정상 작동하는지 확인

**테스트 단계**:

4. 제목, 설명 변경 후 저장
5. 상세 페이지에서 변경 내용 확인

7. 확인 후 삭제
8. 목록 페이지에서 행사 사라짐 확인

**예상 결과**:

- ✅ 모든 단계에서 에러 없음
- ✅ 각 단계의 예상 결과 충족

**검증 항목**:

- 전체 플로우 정상 작동
